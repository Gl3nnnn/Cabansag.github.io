My First Month on TryHackMe: Learning Cybersecurity One Room at a Time

2026 Glenn Patrick Cabansag 6 min read

After my home lab taught me how networks move packets, I wanted to learn the other side: how those networks get attacked and defended. My IT work is mostly support-focused, so cybersecurity felt like a natural next layer. I started with TryHackMe and honestly, the first month was one of the most productive stretches of self-study I've had.

1. Why TryHackMe

TryHackMe builds everything around rooms — guided, browser-based labs with a real Linux machine you can interact with. No expensive VM rig, no scary install script. You follow the task, type commands, answer questions, and learn by doing. That "do it yourself" loop is what kept me coming back.

  • Beginner friendly — a path (Pre Security, Cyber Security 101) holds your hand at first
  • Hands-on — every room gives you a machine and evidence to find
  • Gamified — streak counters and badges turned learning into a habit

2. The Rooms I Started With

I deliberately started broad before going deep. Three rooms carried most of my first month:

  1. Pre Security — the foundation: how the web works, OSI model, and basic security principles
  2. Networking Fundamentals — reviewing DNS, DHCP, and ports from a security-focused angle
  3. Linux Fundamentals — command-line basics I now use daily in my actual job

3. Tools I Got Hands-On With

Reading about tools is boring; using them is not. In my first month I opened each of these for real:

nmap -sV 10.10.x.x     # Enumerate open ports and service versions
hydra -l admin -P list.txt ssh://10.10.x.x   # Password spraying demo
gobuster dir -u http://10.10.x.x -w wordlist.txt

None of this is about attacking real systems — every target here was an intentionally vulnerable lab machine. The point was understanding how these tools behave so I can both defend against them and explain them to teammates.

4. The Biggest Lessons

Cybersecurity isn't about memorizing tools — it's about learning to think like an attacker and being methodical about evidence.
  • Technique matters more than tools. Enumeration first, exploit later. Check every port, look at every service banner.
  • Take notes. I started a markdown folder of commands, flags, and "aha" moments — it's now my personal reference manual.
  • Review Linux basics constantly. Every single room assumed solid terminal skills.

5. What's Next

Next on my list is finishing Cyber Security Awareness and aiming toward CompTIA Security+ prep material. I also want to connect the dots between the home lab and these rooms — segmenting networks and watching the traffic from both sides ties everything together.
