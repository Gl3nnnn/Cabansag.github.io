My AWS Learning Journey: Getting Started

2025 Glenn Patrick Cabansag 7 min read

Cloud computing felt overwhelming at first, but after certifying in Digital Transformation with Google Cloud, I decided to go deeper with AWS. Here's my starter roadmap and the concepts that made everything click.

1. Start With the Big Three Services

Don't try to learn all 200+ AWS services. The foundation tier is really three things:

  • EC2 — virtual servers. Learn to launch, connect via SSH, and run a simple web server.
  • S3 — object storage. Upload files, set bucket policies, and understand availability.
  • IAM — identity and access. Learn users, roles, and the principle of least privilege.

2. Spin Up a Free-Tier EC2 Instance

Hands-on beats reading every time. I launched a free-tier t2.micro, connected with SSH, and hosted a tiny page with Python:

# Install a web server + write a quick page
sudo apt update
sudo apt install -y nginx
echo "<h1>Hello from EC2</h1>" | sudo tee /var/www/html/index.html

3. Manage Firewalls With Security Groups

The default security group blocks most traffic. I opened port 22 (SSH) and port 80 (HTTP) and immediately understood why permissions matter — a misconfigured group can expose your instance to the whole internet. Least privilege is not optional.

4. Docker Changed How I Think About Deployment

Containerizing projects with Docker made my local code run identically in the cloud. A simple Dockerfile plus an image pull means the same app runs on my laptop and on EC2 without setup drama:

docker build -t my-app .
docker run -d -p 8080:80 my-app

5. Keep the Bill at Zero

The biggest fear for a fresh grad is the AWS bill. My rule: use the free tier, always tag resources, and terminate what I'm not using. Checking the billing dashboard after every session is a habit I refuse to skip.

Cloud skills are about making systems scalable and reliable — but wisdom is knowing when to shut things down.

What's Next

I'm moving toward CI/CD pipelines next — building a small project, pushing it to GitHub, and letting an automated workflow test and deploy it to EC2. The path from developer to cloud-ready is just a series of small, repeated experiments.
