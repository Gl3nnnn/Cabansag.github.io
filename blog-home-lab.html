Setting Up My Home Lab: Networking Basics

2026 Glenn Patrick Cabansag 6 min read

Building a home lab is one of the best ways to learn networking hands-on. You don't need expensive gear — an old router, a switch, and a laptop running Wireshark are more than enough to start. Here's how I approached it and the basics I picked up along the way.

1. The Gear

Start simple. My beginner lab consisted of:

  • A home broadband router acting as the gateway and DHCP server
  • An 8-port unmanaged switch so I could plug multiple devices into the same network
  • A desktop and a laptop, one on Ethernet and one on Wi-Fi
  • A Raspberry Pi later on to run a small server and learn Linux

2. Understanding the Topology

Draw it out. The router connects to the internet, the switch hangs off the router's LAN port, and every wired device plugs into the switch. Wireless devices reach the router directly. This flat topology is perfect for learning because traffic is easy to trace.

Internet
   |
[ Router ] ---- [ Desktop ]
   |     \---- [ Switch ] ---- [ Laptop ]
 [Pi/Wi-Fi]

3. IP Addressing and DHCP

By default the router hands out IP addresses via DHCP. I checked which addresses were assigned and learned to spot the difference between the gateway (e.g. 192.168.1.1) and the devices it leases addresses to. From there I practiced setting static IPs so my Pi always had the same address.

Useful commands I kept on hand:

ipconfig /all          # Windows - see your IP, gateway, DNS
ping 192.168.1.1       # Test connectivity to the gateway
tracert 8.8.8.8        # Trace the path to a public host
arp -a                 # View the local ARP table

4. Sniffing Traffic with Wireshark

Wireshark is where it gets fun. I opened it in promiscuous mode on the laptop and watched the traffic flow across my lab. I saw DHCP requests during lease renewal, ARP lookups, and DNS queries when I loaded a webpage. Being able to see the packets makes the theory finally click.

Capturing your own traffic in your own lab is a completely safe way to learn packet analysis — try it before touching production networks.

5. Next Steps

From here I'm planning to segment the lab with VLANs, add a firewall, and eventually learn Cisco CLI with a router simulator or an old managed switch. A home lab turned out to be the best "teacher" — it breaks, and breaking things is exactly how you learn to fix them.
